# Task 6 Report — Phase-C Accessibility Behavior for Shell and Panels

## Root Cause / Design

- Root cause: shell and panel accessibility behavior was split across route-owned components without a consistent baseline for landmarks, Escape close, focus return, and shell-owned status announcements.
- Chosen approach: keep behavior local to Phase-C shell/panel owners by adding route/panel landmarks, shell-local live regions, and opener focus tracking in the editor toolbar path.
- Alternatives considered:
  1. Add shared accessibility primitives now — rejected because Phase B primitives are explicitly out of scope for Task 6.
  2. Add test-only attributes/text to satisfy assertions — rejected because it would not improve runtime accessibility and violates the no-workaround rule.

## Review Fix

Addresses the Task 6 review Important and Minor findings. TDD throughout: tests added/adjusted first and watched failing before implementing.

### Important

1. **Editor panel live region never announces close** (`EditorRightPanelSlot.tsx`)
   - Root cause: the live region lived inside the `<section>`, and `if (activePanel === null) return null` unmounted the whole subtree on close, so screen readers never received `shell.panelClosed`.
   - Fix (option the reviewer endorsed — hoist the status region, matching `StudioWorkspaceShell`): the `role="status"` region is now always mounted and toggles `shell.panelOpened`/`shell.panelClosed` based on `activePanel`; the `<section>` still renders only when a panel is open.
   - Test: `announces panel close in the status region when the active panel is cleared` — RED (region absent after `rerender` to `null`), then GREEN.

2. **`onClickCapture` guard skipped SVG-icon clicks** (`EditorToolbar.tsx`)
   - Root cause: `if (!(event.target instanceof HTMLElement)) return;` rejected `SVGElement`/`SVGPathElement` targets (lucide icons), so `openerRef` was never set for icon clicks and focus return was lost.
   - Fix: guard with `instanceof Element` (SVG elements satisfy this) and use `closest<HTMLElement>("button")` for a typed result.
   - Test: new `EditorToolbar.test.tsx` — `records the opener button when the click lands on an SVG icon` — RED (called 0 times), then GREEN.

3. **Focus-return test could not independently verify the slot's focus logic** (`EditorRightPanelSlot.test.tsx`)
   - Root cause (beyond the reviewer's note): `closePanel = vi.fn(() => opener.focus())` masked the behavior, AND `opener.focus()` at setup left `activeElement === opener` before Escape, so the assertion passed trivially even with the slot's `returnFocusTo.focus()` deleted.
   - Fix: no side effect on `closePanel`, opener is not pre-focused, and `document.body.focus()` is called before Escape so the assertion can only pass via the slot's own focus return.
   - Isolation proof: with the slot's `returnFocusTo.focus()` line temporarily removed, the corrected test FAILS (`activeElement` is `<body>`); restored → passes.
