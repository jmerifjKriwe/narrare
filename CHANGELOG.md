### Fixed

- JWT secret fallback chain in `proxy.ts`: added `process.env.SECRET_KEY` as second fallback (matching backend's env var). Previously only checked `AUTH_JWT_SECRET`, causing verification failures on protected routes when only `SECRET_KEY` was set.

- Setup wizard steps 2↔3 swapped: starter selection now comes before novel details
- WizardStep3 prefills form from metadata.json when a demo starter is selected
- Demo loader reads metadata from files instead of hardcoded data
- EditorSurface refactored to use Autosave TipTap extension

- **ADR-023 — Co-Author Schema Alignment**
  - Co-Author: `CoAuthorPanel` now supports per-change accept/reject toggle (partial apply instead of all-or-nothing)
  - Co-Author: `selection_text.max_length` increased from 2000 to 10000 chars
  - Co-Author: `validate_coauthor()` enforces max 2000 words via SET-005 settings cascade pattern
  - Co-Author: Schema alignments — `type` → `change_type`, `original` → `original_text`, `revised` → `revised_text`, `position` → `index` (simplified), `aggregate_reasoning` → `reasoning`
  - Co-Author: `ChangeDetail.id` type changed from `str` to `uuid.UUID`
  - Co-Author: `FLOW` focus area removed from `CoAuthorFocus` enum (not implemented)
  - Co-Author: `character_id` removed from `CoAuthorRequest` (deferred for future KB context assembly)

- **SET-005 / ADR-060 — LLM retry settings removed from user/project configuration**
  - `retry_max_attempts` and `retry_base_delay` are removed from the user/project token-limit surface: frontend inputs (`SystemTimeouts`), frontend types (`types/settings.ts`), API DTO (`token_limits/schemas.py`), router mapping, validator allow-list, DB override keys, and the resolver (`TokenLimitsService`). They were a false control — resolved but never consumed by any LLM/SSE/WebSocket retry boundary (RULE-18b violation #1).
  - LLM transport retry is now governed at the provider layer (`core/llm/_providers/`) via the operator env var `NARRARE_LLM_TRANSPORT_MAX_RETRIES` (default `2`), read by `core/llm/_transport_retry.py::get_transport_max_retries()` and applied as the SDK client `max_retries` (uniform for `run()` and `stream()`).
  - The Gateway v1 `with_retry` / `RetryConfig` vestige (`packages/core/narrare_core/llm/retry.py`) is retired (zero production callers).
  - `ws_timeout` (WebSocket idle timeout) is **unchanged** — it has a real runtime consumer (`WritingSessionHandler`).
  - Migration: no destructive migration required. Any stored `retry_*` DB overrides are orphan keys, ignored gracefully by the resolver's unknown-key drop behavior; operators should use `NARRARE_LLM_TRANSPORT_MAX_RETRIES` instead.

- **ADR-080 — Remove Redis & TaskIQ for single-user deployment**
  - Redis and the separate worker container are **no longer required** for self-hosting. Narrare now runs as a single API process: background tasks (embeddings, band summaries) dispatch in-process via `asyncio.create_task`, and the cache/session/rate-limit backends are in-memory.
  - Self-hosters no longer configure `REDIS_URL` or run a Redis/worker container. The `redis` + `worker` services, the `redis_data` volume, and `depends_on: redis` were removed from `docker-compose.dev.yml` and `docker-compose.release.yml`.
  - Dependencies dropped: `redis`, `taskiq`, `taskiq-redis`, `taskiq-fastapi`. The `GET /tasks/status` monitoring endpoint and the frontend `BackgroundTasksPanel` were removed (tasks now run in the API process).
  - Scoped to single-user/single-process deployment; the cache adapter contract is preserved so a Redis (or equivalent) backend can be re-plugged if Narrare moves to multi-user/multi-worker operation. See ADR-080.
