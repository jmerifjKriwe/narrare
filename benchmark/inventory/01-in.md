## Findings

1. **KB merge/dedup (KB-009) — `POST /api/v1/novels/{novel_id}/kb/merge`: not benchmarkable as-is.**
   Router decorator and `KBMergeAgent` are implemented (`router_merge.py`, `merge_service.py`), but the router is never included in `_app/main.py` and no frontend client calls it — the route 404s at runtime. Spec §3 lists merge under direction `in`; mounting the router would restore the capability.
2. **Reference resolution — `POST /api/v1/novels/{novel_id}/kb/resolve-references`: direction out/check, not in.**
   Consumes text and returns matched KB entries but writes nothing → handed to Tasks 3/4.
3. **Proactive KB suggestions — `GET /api/v1/novels/{novel_id}/kb/suggestions/{chapter_id}`: direction out/check, not in.**
   Read-only ranked suggestions from `ProactiveContextService` (embedding-based, no `narrare_core.agents` import, no KB write) → handed to Tasks 3/4.
4. **Memory subsystem (`apps/api/narrare/memory/`, mem0-backed): not surveyed for direction in.**
   It writes no `kb_entries`; its KB-program classification is deferred to Task 5 synthesis / baseline analysis (the superseded Knowledge-Contract sub-project's mem0 classification is replaced by the empirical baseline runs, ADR-083 Design History).
5. **Author-voice analysis persists ProjectSettings, not KB — scope decision (register Finding 7 twin).**
   `POST /api/v1/analysis/author-voice/{novel_id}` (SSE; mounted; client: `packages/web/lib/api/author-voice-stream.ts`) persists the `AuthorVoiceProfile` to `ProjectSettings.author_voice` via `AuthorVoiceRepository` (`author_voice_service.py`) — settings surface, not `kb_entries`. Write audit across all mounted `analysis/` routers: character-voice (CAP-IN-09) is the only KB writer; voice-check/voice-drift/author-voice-drift are direction `check` (CAP-CHK-05/06/07); beta-reader, coreference, pov, readability, and sentiment write nothing.
6. **AI timeline analysis GET does not persist — register Finding 8 premise not reproduced in code.**
   `GET /api/v1/planning/timeline/{novel_id}` (mounted; client: `packages/web/lib/api/timeline.ts::getAnalysis`) runs `TimelineAgent` (`timeline_analysis_service.py::generate_timeline`), but the method only returns the transient `TimelineResponse` — no repository write; the service's only `event_repo.create` belongs to `confirm_extracted_event` (CAP-IN-07's confirm). Read-only generative analysis → not direction `in`; no entry forced. The persisting timeline paths remain CAP-IN-07 (extract/confirm) and the manual event CRUD in its Notes. Register correction recorded for `04-findings.md` Finding 8.
