> Status: ✅ Resolved

## Q-009 — Should Chat Conversations Be Project-Scoped or User-Scoped?

> **Status:** ✅ Resolved

**Question:** Does a chat conversation belong to a single project (novel) or to the user across all projects?

### Context

The chat is designed to discuss writing craft and project-specific questions. But some questions span projects — "How do I improve my dialogue?" is universal. The conversation history determines how context is loaded when the author returns to a chat session.

### Option A — Project-Scoped

Each conversation is tied to a `project_id`. When the author switches novels, they see different conversations.

**Pros:**
- Clear data boundary — no accidental context leakage between projects
- Matches existing patterns (KB, chapters, settings are all project-scoped)
- Simple implementation — `WHERE project_id = ? AND user_id = ?`
- Export/delete per project is straightforward

**Cons:**
- Author who works across projects cannot carry a conversation across them
- "General craft" conversations don't belong to any single project

### Option B — User-Scoped

Each conversation belongs to the user. Project context is injected per-message (via the request body), but the conversation itself is user-level.

**Pros:**
- Cross-project continuity — author can discuss multiple novels in one conversation
- General craft conversations fit naturally

**Cons:**
- Data boundary is fuzzy — an exported project may or may not include user-level chats
- Complex filtering — need to tag messages or conversations by project
- Potential for context confusion if the author discusses two novels in one conversation

### Recommendation

**Option A (project-scoped)** for v1. Match existing patterns. If users request cross-project conversations, add a "shared conversations" concept in v2.

## Resolution

**Option A (Project-Scoped) — implemented as designed.**

Chat conversations are project-scoped. `ChatRequestSchema` requires `project_id: UUID`, and `create_conversation()` takes both `project_id` and `user_id` as mandatory parameters. When the author switches novels, they see different conversations. This matches existing data boundary patterns (KB, chapters, settings are all project-scoped).

**See:** ADR-024, `packages/core/narrare_core/chat/schemas.py`, `packages/core/narrare_core/chat/conversation_store.py`

## Q-010 — Should the Chat Prompt Support DE/FR from Day One or English-Only v1?

> **Status:** ✅ Resolved

**Question:** Should the bundled chat prompt be created in English only for v1, with DE/FR following in a subsequent task?

### Context

CR-AUFG-04-07 (KB-Prompts DE/FR) is still open. The chat is a new feature — i18n adds scope to the initial implementation.

### Option A — English-Only v1

Create the EN prompt only. DE/FR users fall back to EN via the existing cascade.

**Pros:**
- Faster v1 delivery — no translation effort
- Existing cascade handles fallback gracefully (all other features do this too)
- Prompt can be refined based on EN usage before investing in translations

**Cons:**
- DE/FR users get English prompts — meaningful but not ideal for craft discussions
- Increases gap noted in FIND-014 (KB-Prompts English-only)

### Option B — Full i18n from Day One

Create EN + DE + FR prompts in the same implementation task.

**Pros:**
- No i18n gap from day one
- Matches the existing meta-prompt pattern (3 languages)
- Better experience for DE/FR authors — craft discussions benefit from native language

**Cons:**
- Adds 1-2 days to implementation (translation + review)
- Prompt may change significantly after v1 feedback — translations become stale
- Blocks v1 delivery on translation availability

### Recommendation

**Option A (English-only v1)** . The existing cascade fallback works. Add DE/FR as a follow-up task (CR-AUFG-04-07 scope or separate). This is consistent with FIND-014's recommendation to prioritize KB prompts for translation first — chat is lower priority for i18n.

## Resolution

**Option A (English-only v1) — implemented as designed.**

The chat prompt exists only in English: `packages/core/narrare_core/prompts/_bundled/writing/en/chat/system.md`. No `de/` or `fr/` variants exist. DE/FR users fall back to EN via the existing prompt cascade, consistent with the FIND-014 recommendation to prioritize KB prompts for translation first. *(Path moved from `_bundled/chat/en/system.md` to `_bundled/writing/en/chat/system.md` by ADR-049, which restored ADR-024 routing and deleted the orphan duplicate. The English-only resolution itself is unchanged.)*

DE/FR chat prompts should be added as a follow-up task under CR-AUFG-04-07 or a dedicated task.
