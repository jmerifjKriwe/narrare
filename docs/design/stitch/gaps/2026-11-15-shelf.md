## Why placeholders exist

The owner's condition is fidelity to the drafts without lies: a feature the
backend cannot serve keeps the draft's geometry with an honest neutral — a
disabled control with the drafted note, never an invented number, never a
fabricated quote. Where the draft itself invents data the archive does not
carry, the element stays out and the omission is argued here instead of
silently dropped. The wave's port reports (Tasks 6–10) disclosed every kept
deviation; this ledger collects the ones that need a trigger, a re-open
condition or a named reason.

Rows come in four kinds:

- **Feature gaps** — a drafted control whose action does not exist yet. It
  renders disabled with the note „kommt mit dem weiteren Aufbau"
  (`writing.shelf.comingSoon`), `aria-describedby` pointing at the note.
- **Draft gaps** — the draft overlooked something or contradicts the backend
  (a search scope the model cannot serve, an archived-card chrome drawn on a
  hand-drawn cover, a banner state the draft never draws). The interim is the
  honest rendering; the trigger is a corrected draft through a Stitch round
  or the named backend fact, never a local invention.
- **Reason rows** — deliberate omissions with no trigger: the draft draws
  invented data or a state that would lie. They return only if the named
  re-open condition becomes true.
- **Owner-decision rows** — the draft is faithful but the product question is
  open (the dialog's slider range, the fr copy voice). The decision is the
  owner's, not the wave's. Row 1 was one until the owner decided it (#863).

### Reading the rows

- **Rows 2–4, 6** are the feature gaps: every disabled control on the live
  shelf whose trigger a wave owes, each with the drafted note and the wave
  that owes the action (row 5's disabled view toggle is an owner-decision
  row below — its trigger is a decision, not a wave). The import door (row 2)
  is the standing row the welcome ledger already carries for the welcome
  card — one wave owes both (the landing room's copy went with the landing's
  deletion, #862).
- **Rows 7–9, 19** are the workspace wave's book-settings family: the
  backend fields exist (`status`, `series_id`/`series_volume`, the inherited
  settings) but no UI writes them; row 9 names the one field the PATCH body
  itself still lacks (`target_words`).
- **Row 1** is resolved: the owner decided the hero carries the menu (#863),
  the Stitch round drew `shelf-hero-menu`, and the hero mounts the grid's
  own surface — the row stays as history, the interim is gone.
- **Rows 5, 10, 13, 28** are owner-decision rows: the port is draft-faithful
  or honestly carried; the open question is the owner's, not a defect. Row 28
  is the hero menu's draft copy the #863 binding omitted (row 1's resolution).
- **Rows 11–12, 27** are the extraction family: capability-local copies rule 1
  forces today, each naming the consumer count or the chrome handover that
  triggers the shared helper.
- **Rows 14–17, 26** are draft gaps the port answered honestly: the search scope
  the model cannot serve, the archived chrome drawn on a frozen cover
  system, the two banner states the draft never draws (error, lapsed), and
  the weekly label whose basis is the window's 30-day mean — the draft's
  label stands, the unit line carries the per-day truth.
- **Row 18** is the standing „Neues beginnen" reading, carried from the W2
  ledger's row 23 with its premise updated: multi-novel is real; the
  assistant/template surfaces are the remaining product question. The
  landing that carried the drafted doors is deleted (#862); the reading
  stands on the shelf alone.
- **Rows 21–24** are reason rows: invented data or a state that would lie.
  They have no trigger — only the named re-open conditions. Row 25 left the
  family: its re-open condition (a daily-goal field) became true in W4, and
  the banner reads it — the row stays as history, the interim is gone.

## What is *not* a placeholder

These ship real and are listed so nobody mistakes them for gaps:

- **The route handover** — `/` is the shelf post-setup and redirects to
  `/setup` (the welcome) pre-setup; the inverse gate sends every post-setup
  `/setup` deep link home. Both gates read one shared status answer
  (`b84a90f4`).
- **Search, filter facets and the archive toggle** — real client-side
  filtering over the loaded list (title/genre/figure search, genre and
  status facets, OR within a group / AND across groups), the archive toggle
  a real server refetch with `include_archived`, never a client hide
  (`7e904fc2`). The empty-search panel answers a real narrowing that yields
  nothing, with one live clear-all door.
- **The quick menu** — duplicate (a real server copy with chapters), export
  (a real ZIP through the typed client, the meta line refetching to the
  fresh `last_exported_at`), archive (the drafted confirm) and restore (one
  click, symmetric) — all through the one PATCH/POST family, with the busy,
  error and retry discipline (`5814b5cd`, `7a2d1081`). The hero wears the
  same menu (#863, the commit `feat(writing): the hero book acts through
  the same quick menu`): one surface, two anchors, and archiving the hero
  re-picks the next active book through the same refetch.
- **The new-book dialog** — three fields, the live cover preview, the
  verbatim inheritance note, a real `POST /api/writing/novels` carrying
  `target_words`; the shelf refetches and the new book appears as hero or
  grid card by its own `updated_at` (`33ec3ca7`, `eeaa2247`).
- **The activity banner and streak** — the real aggregate
  (`GET /api/writing/activity`): the atelier's daily goal with its unset
  neutral, open remainder and reached done-copy (W4 row 25, #891 — the
  hero-book pin ended), the atelier's today-net with its zero/negative
  voices, the weekly average, the sparkline over the window's own points
  (today's dot), the streak chip pluralized with an honest zero. The write
  family invalidates the aggregate beside the novels, so a chapter write
  moves the banner without a reload (`700ca4e4`; backend `1cec524e`,
  `a3a18805`).
- **The metrics strip** — real book count and total words over the active
  population; the streak reads the same aggregate.
- **Status, series and archived reads** — real columns (`7f71530a`): the
  pills, the hero's series line and the „Archiviert" marking render from the
  row, never a default. The duplicate endpoint is real (`d9770eed`).
- **The word pairs and progress tracks** — real `word_count` (server-counted
  from chapters) against the row's own `target_words` (exposed on the read
  schema in `2051b84c`, on the create schema in `33ec3ca7`); a missing
  target is the honest neutral, never a guessed goal.
- **The loading, error and empty states** — the shelf-states draft's
  geometry on the shell's skeleton/retry families: one metrics strip, the
  real failure message with a retry that holds its notice, the blank-book
  panel with its honest doors and the archive door that answers „Keine
  ruhenden Entwürfe" when the archive holds nothing (`2051b84c`,
  `9da233f8`, `5814b5cd`).

## How a row becomes real

1. Land the trigger the row names (a surface, a field, a corrected draft, an
   owner decision).
2. Replace the interim at the element; a disabled control becomes the real
   door, an omitted element returns only if its re-open condition is met.
3. Update the row here (or remove it if nothing is left) in the same commit.
4. If the row earned an issue under the wave's index, close it from that
   commit: `Closes #<n>`. The index closes with its last child.

No placeholder is removed by deleting its slot — the slot is the draft's,
and it stays. Only the neutral content is replaced.
