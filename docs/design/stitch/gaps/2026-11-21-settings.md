## Why placeholders exist

The owner's condition, carried from W3–W6: fidelity to the drafts without
lies. A feature the backend cannot serve keeps the draft's geometry with
an honest neutral — never an invented number, never a fabricated state.
The settings wave adds four rules of its own. The wire contract:
absent-vs-carried-null everywhere (absent keeps the stored answer, a
carried null clears or hands back — `{}` never crosses, that is a client
bug). The novel-update rule on the PUT: only dirtied fields ride a save.
The one-palette rule: a preview depicts its target theme in pinned tokens,
never a literal hex. And no invented driver claims: the offline card
states a driver only on the backend's own answer. The drafts' mock figures
(„h.calder@station7.de", „2.500") are draft data, never shipping data —
the real row answers everywhere.

## Known-pattern notes (no row owed — the pattern is the record)

- **The viewport law's boundary** (Task 2's carry): scrim modals carry
  the containment (`max-h-[calc(100vh-2rem)] overflow-y-auto`, the
  planning family's exact fixed strings); anchored popovers — the
  LoreGraph edge-note — deliberately do not (small fixed content,
  different geometry). A decision, not an accident; the day a popover
  grows scrollable content, the question re-opens at that popover.
- **The settings reads' two-entry shape** (Task 3's disclosed design):
  the chrome's tolerant `useSettingsQuery` (outages answer nulls — the
  boot gate depends on it) and the surface's strict `useSettings()`
  (`["settings", "read"]`) are separate cache entries with opposite
  outage contracts; the `["settings"]` prefix invalidation keeps them one
  family. The rule: a surface that must show the truth reads strict;
  chrome that must survive an outage reads tolerant. #933 (row 3) was the
  family's live edge, closed with the W8 opener; the narrower in-flight
  class remains open as #940 under the W8 index.
- **The doors land on the field** (Task 3's disclosed contract): the menu
  doors and the BookSettings door address their target as FIELD focus via
  the page's hash effect — the drafted focus contracts are dialog-shaped,
  and on a page the field is the honest landing; the hash stays in the
  URL (a real address, not consumed). Boundary worth knowing (Task 5's
  discovery): a same-document hash change (fragment-only `page.goto`,
  `/settings#a` → `/settings#b`) bypasses the router's history adapter —
  the hash effect never refires. The real doors call `router.navigate`,
  which the E2E drives; fresh-load landing is proven once, the second
  address through the real doors. The day a product door changes only the
  hash, its landing is the thing to re-check.
- **The conftest's language-independent ready gate** (Task 5's review
  round): the settings suite's ready gate is the form's submit button —
  never text — because a leg boots in English. Seed-through-HTTP only,
  per-suite database, no database insert anywhere: the knowledge/planning
  conventions, and the offline card's flip leg creates its provider and
  default model through the API (pure resolution, no network leaves).
- **A checked radio's click is no transition** (Task 5's browser-vs-jsdom
  note): a real browser fires no `change` on an already-checked radio,
  unlike `fireEvent` — the language leg orders its clicks so every click
  is a real state change, and the vitest „click Deutsch while
  resolved-de" shape is not reproducible browser-side.
- **The chrome's active face** (Task 3's disclosed ruling): the user menu's
  Einstellungen row wears `aria-current="true"` on its own surface — the
  rail-switcher precedent extended to a real page route, deliberate
  rather than the router's page semantics.

## How a row becomes real

1. Land the trigger the row names (a surface, a field, a corrected draft,
   an owner decision, or user feedback).
2. Replace the interim at the element; a placeholder becomes the real
   thing, an omitted element returns only if its re-open condition is met.
3. Update the row here (or remove it if nothing is left) in the same
   commit.
4. Close the row's child from that commit: `Closes #<n>`. The index
   (#934) closes with its last child.

No placeholder is removed by deleting its slot — the slot is the draft's,
and it stays. Only the neutral content is replaced.
