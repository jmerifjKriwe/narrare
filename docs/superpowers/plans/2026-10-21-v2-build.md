# Narrare v2 — build plan

Six steps. Each one ends with a green E2E through the real UI, the real backend and the
real database; nothing else counts as done. The spec is the authority:
`docs/superpowers/specs/2026-10-21-narrare-v2-architecture-design.md`.

## Steps

- [x] **0. Walking skeleton** — `app/` as a workspace member, `kernel/db` (async session,
      scoped repository base, one Alembic baseline), `capabilities/writing` with novel
      create + list, `api/` mounting it, a Next.js page in `web/`, one Playwright spec.
      *Done when:* a novel typed into the browser is in Postgres and visible after reload.
- [x] **1. Writing: chapter + editor** — chapter CRUD, TipTap editor, manual save.
      *Done when:* text typed into a chapter survives reload.
- [x] **2. Setup** — first run creates the local user and the first novel; `setup`
      capability with its own E2E on an empty database.
      *Done when:* a fresh database opens on setup and lands on the novel.
- [x] **3. Writing: continuity prompt** — chapter-context prompt, streaming through the
      fake provider (first catalog entry). Resolves the pydantic-ai prove-it question.
      *Done when:* streamed text arrives in the editor and is persisted.
- [x] **4. Knowledge base** — upload a document, chunk, embed with pgvector, retrieve.
      Resolves the mem0 and pgvector prove-it questions.
      *Done when:* the uploaded passage is returned by search.
- [x] **5. Chat** — question over the KB, streamed answer with sources.
      *Done when:* the answer cites the passage from step 4.
- [x] **6. Cutover** — delete `apps/`, `packages/`, the old tests and gates; keep 22
      recipes. One commit, no shim.

## Order

The skeleton comes first because every later step is a folder inside it. Writing comes
before setup because the shell needs a page to show; setup then makes the empty-database
path real. The LLM arrives only at step 3, when there is writing for it to extend.
Knowledge base before chat, because chat has nothing to answer from otherwise.

## What each step costs

One capability folder, its tests and its E2E, plus the generated views. No new gate, no
new document, no new required field. If a step seems to need one, it stops and reports
`NEEDS-APPROVAL` with the three statements from spec §8.

## Open before step 3

Hosting model — self-hosted single-tenant or multi-tenant service. The tenancy seam
(`user_id` + scoped repository base) is built in step 0 either way, so this only has to
be settled before an auth UI is designed, and step 5 is the latest point where that
becomes concrete.

## Port ledger — the v1 basis of each capability

The v1 corpus (`docs/features/`) is the input, not the scope (spec §11). Its
`INDEX.md` is the complete inventory of v1 features with the file that describes
each; this table records which v1 feature IDs a v2 capability took as its basis and
how far that basis reaches. An ID with no entry here is one that no port has taken
up yet — that gap is what the table exists to show. Deliberately excluded features
are listed below it, never silently.

| v2 home | v1 basis | What the port took |
|---|---|---|
| `capabilities/writing` | WRITE-001 (Writing Editor) | novel create/list, chapter create/read/update, TipTap editor (StarterKit) with autosave — the v1 control surface (formatting bar, chapter versions) is not ported |
| `capabilities/writing` | WRITE-003 (AI: Extend Chapter) | one streamed continuation appended to the chapter as written — the v1 length options (short/medium/long) and context controls are not ported |
| `capabilities/setup` | SETUP-001 (Setup Wizard) | the create path only: local user + first novel on an empty database; the 5-step wizard, demo content (SETUP-002) and provider UI (SETUP-004) are not ported — a provider is one catalog entry (spec §5) |
| `capabilities/knowledge` | INFRA-004 (Embedding Store) | document upload, chunking, embedding, pgvector search and re-embed — the v1 entity KB (KB-001 … KB-010, WIKI-001) has no v2 home yet |
| `capabilities/chat` | CHAT-001 (Free-Form Chat) | one question over the KB, streamed answer with its sources; no persisted session |

**Parked (spec §11)** — registered, never built, never ported silently: WRITE-008
(multi-draft generation), WRITE-013 (writing workflows), KB-010 (editor-integrated
knowledge graph).

**Outside the core scope (spec §11)** — the core is writing, knowledge base, chat and
setup. Every other area table in `docs/features/INDEX.md` (series, notes, wiki,
analysis, planning, consistency, adaptive/coaching, analytics, prompt customisation,
import/export, adapters, …) is re-decided on merit before anything of it is built.
