# E2E cadence and CI parallelism — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep every capability's real-UI E2E as a merge gate while running only the affected
suites by default — locally and in CI — and cut the full CI wall clock from 8:41 to about
4:10 by running the six capability suites in parallel behind one `e2e` check.

**Architecture:** One stdlib resolver (`scripts/affected.py`) maps a path list to capability
names and is the only place the mapping lives; `just` uses it for the local gate, the CI
`changes` job uses it to fill a matrix, and a small aggregator job keeps the single required
check name `e2e`. The mapping is fail-open: anything it does not recognise yields every
suite.

**Tech Stack:** Python 3.14 stdlib (script + pytest), `just`, GitHub Actions (matrix,
`needs`, job aggregator). No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-21-narrare-v2-architecture-design.md` §6, §7, §8 —
read with the design doc `docs/superpowers/specs/2026-10-31-e2e-cadence-design.md` this plan
implements.

## Global Constraints

- "A capability is done only with a green E2E that drives the real UI, the real backend and
  the real database" (`docs/_shared/CONSTRAINTS.md` rule 2) — this change moves *when* it
  runs, never *whether* it can be skipped silently.
- "`just --list` is the whole command surface: 22 recipes, no hidden gates" (`AGENTS.md`) —
  the new scope is a parameter, not a recipe.
- A gate counts only when its output was read (`AGENTS.md`, Verify).
- `--no-verify` and force push are forbidden; conventional commits; nothing is committed
  before the review is green.
- The local gate must prove no less than CI on the same tree.

## Review Focus

- **A path the mapping does not know** (new top-level directory, a file moved out of
  `app/capabilities/`): expected every suite, not silence. Task 1.
- **`changes` failing** (script crash, git unavailable): expected a red `e2e`, never a
  skipped-therefore-green check. Task 4.
- **An empty matrix** (a change owing nothing): expected a skipped matrix job and a green
  aggregator with a notice, not a workflow error. Task 4.
- **A stale base locally** (branch behind `main`, or a detached HEAD): expected the
  merge-base of the default branch, and all suites when no base can be resolved. Tasks 1, 2.
- **A release PR** that touches a lockfile: expected no suites (the allowlist wins over the
  shared-surface table), so release-please does not pay six runners per push. Task 1.

### Task 1: The resolver — `scripts/affected.py` and its tests

**Files:**
- Create: `scripts/affected.py`
- Test: `app/kernel/tests/test_affected.py` (tests must live under `app/`, `testpaths = ["app"]`)

**Interfaces:**
- Consumes: nothing (stdlib only — it runs in the `changes` job before `uv sync`).
- Produces:
  - `CAPABILITIES: Path` (`Path("app/capabilities")`)
  - `SHARED: tuple[str, ...]` — the shared-surface prefixes; `INERT: tuple[str, ...]` — the
    paths that owe nothing; `RELEASE: frozenset[str]` — the release-please allowlist.
  - `class Resolution(NamedTuple): capabilities: list[str] | None; reason: str` — `None`
    means every suite, `[]` means none.
  - `def resolve(paths: Sequence[str], *, known: set[str] | None = None, release: bool = False) -> Resolution`
  - `def known_capabilities() -> set[str]` (directory names under `CAPABILITIES` that hold
    an `e2e/` directory)
  - `def default_base() -> str | None` — the remote's default branch, else `narrare/main`,
    else `origin/main`, else `None`.
  - `def changed(base: str | None, *, worktree: bool) -> list[str] | None` — `None` when the
    range cannot be read; otherwise the changed paths, plus the working tree's
    (staged, unstaged, untracked) when `worktree`.
  - `def main(argv: Sequence[str] | None = None) -> int` with the CLI below.

  CLI contract:
  - `affected.py --json [--base REF | --all | --none] [--release-pr] [--worktree]` — stdout
    is a JSON array of capability names (`[]` = none). `--all` expands to every known
    capability; `--none` prints `[]`. Reason and any warning go to stderr.
  - `affected.py --paths SCOPE` — SCOPE is `affected` (default), `all`, or a capability
    name; stdout is space-separated `app/capabilities/<name>/e2e/` paths, nothing when none.
  - Exit status is 0 on every resolution, including fallbacks. A non-zero exit means the
    script itself is broken (import error, bad usage).

  Path table, verbatim:
  - shared → all: `app/kernel/`, `app/api/`, `app/generated/`, `web/`, `i18n/`,
    `app/conftest.py`, `app/capabilities/conftest.py`, `justfile`, `pyproject.toml`,
    `uv.lock`, `pnpm-lock.yaml`, `.github/workflows/ci.yml`
  - capability → that suite: `app/capabilities/<name>/` with `<name>` in
    `known_capabilities()`
  - inert → none: `docs/`, `README*`, `CHANGELOG.md`, `LICENSE`, `AGENTS.md`,
    `CONTRIBUTING.md`, `TESTING.md`, `scripts/`, `docker-compose*.yml`,
    `.pre-commit-config.yaml`, `.release-please-manifest.json`, `.github/` except `ci.yml`
  - anything else → all
  - `release=True` is checked **first**: when every path is in `RELEASE`
    (`{"pyproject.toml","uv.lock","CHANGELOG.md",".release-please-manifest.json","package.json","web/package.json","app/kernel/version.py","web/lib/api/openapi.json"}`),
    the result is `[]` even though `pyproject.toml` and `uv.lock` are shared surfaces.

- [ ] **Step 1: Write the recipe**

```just
# Every capability E2E: real browser, real API, real Postgres. Default: only the
# suites the change touches; `all` or a capability name is the explicit call.
test-e2e scope="affected":
    #!/usr/bin/env bash
    set -euo pipefail
    paths=$(uv run python -m scripts.affected --paths "{{scope}}")
    if [ -z "$paths" ]; then
      echo "no capability touched — no browser suite owed"
      exit 0
    fi
    uv run pytest $paths -v -m e2e --timeout=60
```

### Task 4: Six suites in parallel behind one `e2e` check

**Files:**
- Modify: `.github/workflows/ci.yml` (split the current `e2e` job into `e2e-suites` and `e2e`)

**Interfaces:**
- Consumes: `needs.changes.outputs.capabilities` (Task 3).
- Produces: matrix job `e2e-suites` (entry name `e2e (<capability>)`) and aggregator job
  named exactly `e2e`, which is the required check in ruleset 25754993. The required-check
  names (`tests`, `e2e`, `lint-types`, `build`) must not change.

- [ ] **Step 1: Write the matrix job**

```yaml
  e2e-suites:
    needs: [lint-types, changes]
    if: needs.changes.outputs.capabilities != '[]'
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        capability: ${{ fromJSON(needs.changes.outputs.capabilities) }}
    name: e2e (${{ matrix.capability }})
```

Same postgres service and setup steps as today's job; the run step is
`uv run pytest app/capabilities/${{ matrix.capability }}/e2e/ -v -m e2e --timeout=60`.
`fail-fast: false` is required: a red writing suite must not hide whether knowledge is red too.

- [ ] **Step 2: Write the aggregator**

```yaml
  e2e:
    name: e2e
    needs: [changes, e2e-suites]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - name: Every owed suite passed, or none was owed
        env:
          CHANGES: ${{ needs.changes.result }}
          SUITES: ${{ needs.e2e-suites.result }}
          CAPABILITIES: ${{ needs.changes.outputs.capabilities }}
        run: |
          if [ "$CHANGES" != success ]; then
            echo "::error::the changes job did not succeed; a change owes suites it cannot name"; exit 1; fi
          if [ "$CAPABILITIES" = '[]' ]; then
            echo "::notice::no capability owed a browser suite"; exit 0; fi
          if [ "$SUITES" != success ]; then
            echo "::error::e2e suites ended $SUITES"; exit 1; fi
```

- [ ] **Step 3: Prove the four outcomes in CI, in this order**

  1. **One suite**: a push touching only `app/capabilities/writing/…` → exactly one
     `e2e (writing)` check, `e2e` green. Record the job's wall clock.
  2. **Every suite**: the branch as it stands (touches `justfile`) → six checks, `e2e` green,
     and the `e2e` job's own runtime is a few seconds. Record the wall clock; expected ~4:10.
  3. **Nothing owed**: a docs-only push → no `e2e (…)` check at all, `e2e` green with the
     notice. This is the proof that an empty list is a decision, not a broken workflow.
  4. **Red side, twice**, on a throwaway branch that is deleted afterwards:
     - one writing E2E test made to fail → `e2e (writing)` red **and** `e2e` red;
     - the `changes` step forced to `exit 1` (everything else intact) → `e2e` red with the
       "changes job did not succeed" error, and **no** green check. This is the hole this
       task closes: today a failed `changes` leaves `e2e` skipped, and skipped passes.

  Paste each run id and the check names into the task report.
