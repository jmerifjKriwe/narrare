## Review fix round (post-approval)

Reviewer findings 1+2 (both MINOR) resolved:

1. **Fake foreign-id fidelity** — `FakeScenePlanRepository.bulk_replace` previously
   silently overwrote `_scenes[id]` for an incoming id owned by a different chapter
   (real repo: INSERT → PK collision → `IntegrityError`). Fixed with an unconditional
   up-front raise (`IntegrityError`, `scene_plans_pkey` message — house construction
   style per `test_join_apply.py`) before any mutation, so state mirrors the
   rolled-back failed flush. Design choice: direct raise, no `foreign_id_error`
   toggle — the real collision is deterministic (every foreign-id insert collides),
   unlike `FakeTxSession.commit_error` which models an optional fault. Tests added:
   `test_foreign_scene_id_raises_integrity_error_state_unchanged` (raise + nothing
   stolen/moved) and `test_foreign_chapter_id_row_takes_insert_path_pk_collision`
   (real repo pins the insert path — `session.added` — whose flush is the DB-side
   collision).
