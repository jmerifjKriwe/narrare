## What was implemented

Two new ADR-049 D11 context modes on `LLMIntent.PLAN` (ADR-096 / spec §6.1–6.2),
landing template + route_table + manifest together:

- **`packages/core/narrare_core/prompts/_bundled/planning/en/scene_plan_draft/system.md`**
  (new, 69 lines) — story-structure-planner role; Input section documents the
  category-3 run-prompt XML (`<chapter_context>`, `<instruction>` — never
  templated); Output Format = JSON array of scene objects with exactly the
  `SceneProposal` field set (`title`, `pov_character_name`, `location_name`,
  `present_characters[{name, goal}]`, `purpose`, `conflict`, `resolution`,
  `beats` — matching T6's `scene_plan_types.py` 1:1); guidance 3–8 scenes,
  "each scene must change something (a situation, a relationship, a piece of
  knowledge, or the stakes)"; Do-NOT forbids prose, >8/<3 scenes,
  contradiction of neighbouring summaries, and id/position/status fields.
- **`packages/core/narrare_core/prompts/_bundled/planning/en/scene_plan_refine/system.md`**
  (new, 66 lines) — scene-refinement-specialist role (single-scene constrained
  rewrite); Input documents `<scene_plan>`, `<chapter_context>`,
  `<instruction>`; Instructions demand preserving the scene's narrative role /
  position intent unless the instruction redirects; Output Format = "exactly
  one scene object", same shape as draft; Do-NOT forbids adding/dropping/
  reordering scenes (never a new plan).
- Both templates: frontmatter `prompt_type: planning`, `prompt_language: en`,
  `prompt_version: "1.0.0"`; single `## System Prompt` L2 header
  (PROMPT-L2-HEADERS); placeholders limited to the optional
  `{{project_title}}` / `{{genre}}` / `{{writing_language}}`
  (temporal_consistency pattern — spec §6.2: no required variables; chapter/
  scene data is category-3 runtime data).
- **`packages/core/narrare_core/prompts/route_table.py`** (+7) —
  `scene_plan_draft` + `scene_plan_refine` added to
  `ROUTE_CONFIGS[LLMIntent.PLAN].allowed_context_modes` with an ADR-096
  comment (draft-vs-refine semantics, no overlap with the five existing
  modes).
- **`scripts/architecture/prompt-surface-manifest.yaml`** (+24) — two PLAN
  `context_modes` entries mirroring the `character_arc` entry shape:
  `content_type: customizable_feature_prompt`, `required_variables: []`,
  `optional_variables: [project_title, genre, writing_language]`,
  `security: {xml_required: [], generated_suggestions_must_be_labelled: []}`,
  `fallback_policy: fail_loudly_if_bundled_missing` (per plan Step 4 /
  spec §6.2), each with an ADR-096 provenance comment.
