## Deviations

1. **Fifth production file `_scene_ai_support.py`** (plan listed 4) — the inherited
   service was already 335 lines and the enforced gate is 300; RULE-04 mandates
   modularize-never-compress, so run-prompt assembly + output mapping moved to a
   support module (exact `_story_suggest_support.py` precedent cited in the plan's
   reference service).
2. **Slice a2 at 367 LOC > 250** — direct consequence of (1): the service (237) +
   support (130) are the minimal gate-legal, doc-complete shape. Declared for
   coordinator visibility; no comments/docstrings were stripped to fit.
3. **Registry + probe-script edits** (outside the plan's T8 file list) — required by
   the binding T7 carry-forward ("T8 is the runtime-adoption task"): registry modes +
   probe registration + `.evidence` refresh + `prompt_path_compliance` declarations.
   `check_adoption` exits 1 without the declarations, so these are gate-mandatory,
   not optional polish.
4. **`scene_count` rides the draft `<chapter_context>`** when > 0 (as a `Scene count:`
   line) — spec §5.2 wires `scene_count` ("0 = model chooses") but the plan's
   chapter-context enumeration omits it; the model can only honor it as run-prompt
   data. Minimal spec-gap resolution, category-3 data only (no framing).
5. **Zero-write HTTP proof compares aggregate rows, not the envelope** —
   `version_updated_at` is a per-request derived value on an empty aggregate (T5
   behavior), so envelope equality is not a valid write-probe; row equality is.
6. **`run_limit_resolver` optional ctor kwarg** beyond the plan's interface signature —
   parity with `StorySuggestService`'s DI seam; the plan's constructor signature
   remains valid as-is.
7. **Review-round NIT fix:** `router_scenes.py` dropped its `tags=["planning"]`
   (parent planning router already applies the tag — the sub-router re-declaration
   duplicated `"tags": ["planning", "planning"]` onto all four scene operations in
   `openapi.json`; regenerated, zero duplicates, routes semantically unchanged).

## Concerns

- The zero-write contract is enforced behaviorally (fake repos record every call;
  HTTP-level aggregate-unchanged pin). Nothing statically forbids a future repo write
  inside `SceneAIService` — the guard is the test suite, not a checker rule.
- `scene_repo` is injected per the binding interface but unused at runtime (draft/
  refine are fully stateless; the aggregate PUT is the write path). The interface
  pins it for the protocol shape; T14's removal pass may revisit.
- Integration happy paths patch the factory's `get_model_routing_resolver` /
  `get_model_registry` seams (import-namespace patching, precedent:
  `test_memory_analyze_api.py`). If the factory's import style changes, those patch
  targets must follow.
- `DefaultRunLimitResolver` runs for real in the happy paths; a stale models.dev cache
  degrades gracefully to defaults (observed; RULE-20 guard blocks unit-side).
