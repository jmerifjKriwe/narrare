## Review fix round (post-review, FINDINGS: 1 MAJOR + 2 MINOR)

**F1 [MAJOR] — SceneForm refine snapshot revert (class fix).** The audit row
above originally called the refine apply "sound"; that was wrong for the
async-merge class: `handleRefine`'s `onSuccess` merged the proposal over the
click-render `scene` snapshot, so edits typed while the call was in flight
(only the button is disabled, inputs are not) were silently reverted.
Correction: proposal now merges over a `sceneRef` mirror kept in sync with the
`scene` prop via effect (`useEffect(() => { sceneRef.current = scene; },
[scene])`) — the same latest-state pattern as `ScenePlanEditor`'s
`scenesRef`. The disable-inputs alternative was rejected: list editors live in
`SceneListEditors.tsx`, so full-input disabling cannot close the class inside
`SceneForm.tsx` alone. `SceneForm.tsx` stays at exactly 200 lines (placeholder
attributes on the two aria-labelled inputs dropped to fit — aria-labels are
the a11y contract). Regression test
`keeps edits typed while the refine call is in flight (no snapshot revert)`:
controlled-parent harness (Host feeds emitted scenes back into the prop),
MSW handler delayed 50 ms, status edited mid-flight, asserts the final
onChange carries the mid-flight `status: "in_progress"` AND the proposal's
`purpose` + identity. Proven to bite: with the snapshot merge restored as a
mutation probe the test fails (status reverts to `planned`); note proposal
CONTENT fields (title, purpose, …) intentionally replace local edits — the
contract under test is that non-proposal fields survive.

**F2 [MINOR] — silent empty draft.** A `200 { proposals: [], ai_unavailable:
false }` draft returned with no feedback. `draftEmpty =
ai_unavailable || proposals.length === 0` now drives the graceful
`aiUnavailable` notice (reusing the existing key — no new i18n keys in this
round); the no-save guard is unchanged. Regression test added (zero-proposal
draft → notice shown, zero PUTs). `ScenePlanEditor.tsx` stays at exactly 200
lines.

**F3 [MINOR] — planningUrlState `"scenes"` coverage.** Added parse case
(`planning=1&planningTab=scenes` → `{ open: true, tab: "scenes" }`) and the
previously uncovered serialize-side case (`{ open: true, tab: "scenes" }` →
`"planning=1&planningTab=scenes"`) to `planningUrlState.test.ts`.
