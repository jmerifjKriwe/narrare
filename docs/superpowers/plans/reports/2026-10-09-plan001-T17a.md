## Summary

`chapter_outlines.planned_beats` is gone. Alembic `0049_drop_planned_beats`
(parent `0048_generation_scenes`) implements the spec §3.3 semantics in both
directions: upgrade reverse-migrates scenes → beats while the column still
exists (one beat per scene, ordered by `position`: `title→title`,
`purpose→description`, `status=="complete"→completed`) and then drops the
column; downgrade recreates the 0013 shape (JSONB, nullable,
server default `'[]'::jsonb`) and repopulates it with the only restorable
projection — the same scene-derived beats. Documented data loss: historical
beat-only content is not recoverable and the projection drops scene-only
fields (conflict/resolution/per-scene beats/hybrid refs); downgrade remains an
explicit user action (ADR-095/0046 stance), stated in the migration docstring.

The ORM column is removed from `ChapterOutline` in the SAME task (RULE-14).
Every ORM-level fake/factory referencing the column is updated
(`_ref_index_fakes.make_outline`, `test_ref_index_helpers._outline`), and the
0047 round-trip test was restructured to seed at its parent revision (the
legacy column no longer exists at head — seeding there would fail).

**Fresh-start handling:** the prior interrupted dispatch left one unverified
artifact, `tests/integration/test_migration_0049_round_trip.py` (untracked).
It was reviewed, kept essentially as authored (its assertions match the task's
round-trip contract), and verified green against the real migration — seed at
head → downgrade to `0048_generation_scenes` (column back, beats
reverse-migrated) → re-upgrade (column dropped again; scenes untouched incl.
lossy fields). No other inherited state existed.
