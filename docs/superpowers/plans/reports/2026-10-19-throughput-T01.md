## 1. What was implemented

`catalog.yaml` is now the single source of truth for the provider set, and
`scripts/generate_provider_catalog.py` renders the Core-side Python artifact from it. No
handwritten surface was modified — this task only *creates* the SSOT, the generator, the
generated artifact and its test. Tasks 3/5/6 extend the generator and derive/parity-check the
remaining handwritten surfaces.

The catalog carries the seven providers in canonical display order (`anthropic`, `openai`,
`google`, `groq`, `ollama`, `openrouter`, `zai`) with the verbatim values from the verified
sources: env names are the plain upper-cased `CoreSettings` field names (`CoreSettings` sets no
`env_prefix`; only ADR-071 fields with an explicit `validation_alias` use `NARRARE_*`), and
`pydantic_ai_extra` is the closed set of the seven pydantic-ai provider integrations (verified
against `_providers/*.py`, including `pydantic_ai.providers.zai.ZaiProvider`).

Generator surface, exactly as the brief specifies (load-bearing for T3/T5/T6):

| Symbol | Kind | Notes |
|---|---|---|
| `REPO_ROOT`, `CATALOG_PATH`, `PY_OUTPUT`, `TS_OUTPUT` | module-level `Path` | `TS_OUTPUT` declared but not consumed in this task (T3 renders it) |
| `ProviderSpec` | frozen dataclass | the eleven brief fields, in the brief's order |
| `load_catalog(path)` | function | validates and returns specs in catalog order |
| `render_python(specs)` | function | returns the artifact text (trailing newline) |
| `main(argv=None)` | function | default writes `PY_OUTPUT`; `--check` compares bytes, exit `1` + unified diff on drift |

`load_catalog` rejects, all with a message naming the provider and the field:

* unknown field / missing field (`_validate_field_set`),
* duplicate provider `id`,
* `id` outside `[a-z0-9_]+`,
* wrong value type for every field (string / optional string / bool),
* `pydantic_ai_extra` outside the closed seven-name set,
* `cache_policy` outside `{anthropic_cache_control, automatic, none}`,
* `pricing_default` that is not a mapping, has an unknown rate key, or a non-numeric `input`/`output`,
* `fallback_models` that is not a non-empty list of non-empty strings.

`render_python` emits, in order: the AUTO-GENERATED header (ADR-099 wording), the source and
regeneration comments, the module docstring, `from __future__ import annotations`,
`from enum import StrEnum`, `__all__`, `class AIProvider(StrEnum)` with one member per spec,
`PROVIDER_IDS` as a literal tuple, `PROVIDER_LABEL_KEYS` as a literal dict keyed by member.

## 5. Self-review findings

1. **Deviation from the brief's test listing (F401).** The test body given in the brief imports
   `from pathlib import Path` without using it; `just lint-file` fails with `F401`. I removed
   that single unused import line. All four test functions, their names, the assertions and
   `EXPECTED_HEADER` are exactly as specified; nothing else was touched. Without this the test
   file cannot pass the repo's own lint gate.
2. **`__all__` order.** Ruff's `RUF022` ("`__all__` is not sorted", isort-style: all-caps names
   before CamelCase) rejected the natural order, so the template emits
   `["PROVIDER_IDS", "PROVIDER_LABEL_KEYS", "AIProvider"]`. The member set is unchanged; the
   artifact stays ruff-clean by construction, which is the property the test asserts.
3. **`_check`/write path robustness (root-cause, not a patch).** While verifying the `--check`
   failure path, `PY_OUTPUT.relative_to(REPO_ROOT)` raised `ValueError` whenever the artifact
   path lies outside the repo — which is exactly the situation a later task or a mutation test
   creates by pointing `PY_OUTPUT` at a temp file. Replaced both call sites with a 6-line
   `_display()` helper that falls back to the absolute path. The `--check` mismatch path now
   prints the diff and the message and returns `1` in every layout.
4. **Pyright strict on the generator required `cast`-based narrowing.** `yaml.safe_load` returns
   an untyped value; `isinstance` narrowing of `Any` yields `dict[Unknown, Unknown]` under this
   config, which trips `reportUnknownVariableType` / `reportUnknownArgumentType`. Resolved with
   explicit `Any`-annotated intermediates and `cast` — no suppressions.
5. **Not overbuilt.** Nothing beyond the brief: no TS renderer, no parity invariants, no
   pre-commit/justfile/CI wiring, no runtime loader, no edits to any existing surface. The two
   closed literal sets (`pydantic_ai_extra`, `cache_policy`) are validated because ADR-099 §2
   defines them as closed and ruling 2 names the closed seven-name set.
6. **Completeness against the brief.** Steps 1→5 executed in order with the named commands; every
   produced name (`ProviderSpec` fields and order, `CATALOG_PATH`, `PY_OUTPUT`, `TS_OUTPUT`,
   `REPO_ROOT`, `load_catalog`, `render_python`, `main`, `AIProvider` members, `PROVIDER_IDS`,
   `PROVIDER_LABEL_KEYS`) matches the brief exactly; all four `--check`-relevant artifact
   properties (header, no suppressions, trailing newline, byte equality) are asserted by the test.

## 7. Fix round 1 — `label_key` namespace corrected (coordinator finding F1)

**Finding:** the catalog carried `settings.providers.<id>`, which does not resolve. The web app
mounts each i18n message file under its own file stem (`packages/web/lib/i18n/request.ts:65-68`
sets `messages[ns] = mod.default` for `ns` in `namespaces`, which includes `"settings-ai"`), the
seven provider labels live under `providers.<id>` in
`packages/i18n/messages/{en,de,fr}/settings-ai.json`, and
`packages/i18n/messages/*/settings.json:63` defines `providers` as the *string* `"Providers"` (the
section title). A `settings.providers.<id>` lookup would therefore resolve against a string.
Fully-qualified key: `settings-ai.providers.<id>`.

  `settings.providers.<id>` to `settings-ai.providers.<id>`. No other field touched; ids, order,
  env names, pricing, cache policies and fallback model lists are unchanged.

  inside `PROVIDER_LABEL_KEYS` are the only diff; the enum, `PROVIDER_IDS` and all formatting are
  untouched).
* `scripts/generate_provider_catalog.py` — **unchanged**; the renderer is value-agnostic, which is
  exactly why the fix propagated through regeneration alone.
* No test file change was needed: the artifact round-trip test asserts byte equality with a fresh
