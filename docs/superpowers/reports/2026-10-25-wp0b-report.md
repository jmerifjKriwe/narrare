## Final whole-branch review and the fix wave

The broad review ran on the repo's reviewer model, not the implementers' — deliberately,
so the seam pass is not the same model agreeing with itself. It returned SPEC FAIL with
one HIGH and three MEDIUM findings, each reproduced with a Playwright script
(`/tmp/opencode/wp0b-review/`):

1. **HIGH — a body-less non-2xx was still worn as "Gespeichert".** openapi-fetch parses
   `error` from the body; a proxy 502 or a bare 413 has none, so `error` was `undefined`
   and the write looked saved. Fixed: success requires `error === undefined && response.ok`;
   `editorApiServer` grew an empty-502 mode and a unit test.
2. **MEDIUM — the guard missed the top bar and browser history.** Only the shelf link was
   guarded; `/chat` and Back lost the text. Fixed with TanStack Router's `useBlocker`
   (R5): one place for every router navigation and the unload prompt; the manual link
   handler and the manual `beforeunload` effect are gone. It blocks only destinations
   outside the book's own subtree, so a dock or a focus step is no leave (proven in the
   E2E, which now also opens the Chat dock with a failed save and expects no dialog).
3. **MEDIUM — `saving` was treated as nothing-to-lose.** A hung PUT left text that a
   close or reload dropped without asking. Fixed (R7): anything but `idle`/`saved` is
   unsaved, for every guard.
4. **MEDIUM — a stale success could paint "Gespeichert" over newer text, and an older PUT
   answering after a newer one overwrote the page cache and the server row.** Fixed (R6):
   writes are serialized — a flush waits for the one on the wire and then carries the
   latest body; a success says "saved" only when nothing newer is pending.

LOWs also taken: a stale attempt reports `stale` (not `failed`), so `leave` stops asking a
question after the page is gone; clicking the already-active chapter no longer asks a
false leave; the report's numbers are corrected.

Two tests changed as a consequence, and that is a behaviour change, not a tidy-up:
`loses no text when the ghost is accepted while a save is in flight` now answers the held
write before expecting the queued one (concurrent PUTs are impossible by design under
R6), and the test drain became a quiet-period loop (a serialized straggler can arrive
after the request it queued behind was answered, spending the next case's one-shot).

**Limitation, stated plainly: the wave itself has no independent review.** The subagent
seats hit a five-hour provider limit right after the final review, so the coordinator
implemented this wave and ran the gates itself (`just check`, frontend three times,
writing E2E, all-capability E2E, `just verify` exit 0). The red side is the reviewer's
repro scripts, not a second reviewer's verdict. That is the one place in this branch where
implementer and reviewer were the same context.

## Deviations from plan §3.6 (as designed and delivered)

1. **Five states, not four.** `pending` is needed: the guard must tell "nothing
   to lose" from "inside the 800 ms debounce", and `idle` is both.
2. **The guard covers in-app leaving, not just tab close** — coordinator
   decision, approach 2. `beforeunload` alone cannot see a chapter switch, which
   is a remount. Three call sites: rail button, "Neues Kapitel", shelf link.
3. **The confirm follows a failed flush, not a pending body.** The switch tries
   to save first; only a failure asks. A dialog on every switch inside the
   debounce would be noise, and the automatic flush already covers that case.
4. **The unmount-flush moved.** It no longer re-fires per chapter switch; the
   switch's own `leave` is the flush. The hook keeps it for page teardown.

## Residual, unfixed (plan Review Focus, accepted)

**A PUT that is accepted and never answered.** The close and reload paths now ask (R7:
`saving` counts as unsaved), so the tab cannot lose the text silently. What stays is the
wait: a chapter switch or a navigation waits for the flush to settle before proceeding —
the page's own load already behaves this way, and the indicator stays `saving`, never
"Gespeichert". Not a new convention, not a new hole.

## Accepted residual LOWs (final review, named by the reviewer)

- The E2E test name says "closing a tab" while it exercises `page.reload()`:
  `page.close(run_before_unload=True)` does not run beforeunload handlers on this build
  (playwright 1.61 / chromium-1228, beacon-probed), so the brief's form cannot observe the
  guard for any implementation. The real unload dialog is the one the reload shows.
- The jsdom `beforeunload` test cannot use the router blocker (jsdom has no router), so it
  dispatches the event into a listener the Harness wires. Since the wave that listener
  calls the same exported `unsavedStatus` the page hands to the blocker — shared code, not
  a copy — but the wiring itself is only proven by the E2E reload test.

  slow write delaying the next one by its own latency, acceptable against a local API.

  silently; the cost is that a close during a healthy 30 ms write also asks.

  consequences of R6 and are documented in the wave section rather than hidden in a diff.
